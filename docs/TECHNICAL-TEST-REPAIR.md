# Technical test repair

Implementation status: **offline only; not installed or delivery-qualified**.

A technical test defect must not require artificial implementation failures to
reach the CTO. The new `repair_tests` diagnostic disposition binds the incident,
source execution, current CTO experiment, frozen tests, explicit paths and cases.
It grants permission to produce a correction, never permission to approve tests,
resume implementation directly, or declare delivery.

## Implemented path

- A settled blocked implementation with a completed CTO hold and experiment may
  receive one idempotent scope-diagnosis card. Historical triage continuations
  retain their prior contract.
- The CTO records a structured scope. Controller admission revalidates immutable
  identities and the current graph; pending effects or changed source prevent
  succession.
- Replacement test, implementation and integration cards reuse the existing
  durable graph mechanism. Original cards and snapshots remain historical.
- Contract 3 preserves assertion expressions and enclosing syntax structure;
  independent semantic review and fresh behavioral evidence remain necessary.
- Historical receipt contracts are not upgraded retroactively.

## Qualification completed

511 offline unit tests pass. Coverage includes blocked-source succession without
synthetic retry consumption, unchanged historical cards, downstream dependency
rewriting, crash before/after graph persistence, and idempotent activation.
The installed cancellation incident also passed read-only scope eligibility
against its actual receipts, without recording an authorization or calling a
model. These checks do not qualify a live handoff or homologation.

Legacy correction now creates a scoped baseline projection: original product,
original test inventory, and only the authorized existing test substitutions.
Both original and corrected baselines are observed. The corrected baseline must
pass; unrelated original failures block the repair. Every corrected case becomes
a mandatory negative-control target. CI accepts the exact revised suite only
after a new independent freeze. Unit tests reject altered projections and
self-review. Case-level boundaries also protect neighboring tests, helpers,
imports, method definitions, assertion conditions and early exits.
