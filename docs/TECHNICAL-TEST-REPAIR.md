# Technical test repair

Implementation status: **installed; live assisted release completed with independent review, CI, rollback and post-deploy QA**.

A technical test defect must not require artificial implementation failures to
reach the CTO. The new `repair_tests` diagnostic disposition binds the incident,
source execution, current CTO experiment, frozen tests, explicit paths and cases.
It grants permission to produce a correction, never permission to approve tests,
resume implementation directly, or declare delivery.

## Implemented path

- A settled blocked implementation with a completed CTO hold and experiment may
  receive one idempotent scope-diagnosis card. Historical triage continuations
  retain their prior contract.
- The CTO records a structured scope. Controller admission revalidates immutable
  identities and the current graph; pending effects or changed source prevent
  succession.
- Replacement test, implementation and integration cards reuse the existing
  durable graph mechanism. Original cards and snapshots remain historical.
- Contract 3 preserves assertion expressions and enclosing syntax structure;
  independent semantic review and fresh behavioral evidence remain necessary.
- Historical receipt contracts are not upgraded retroactively.
